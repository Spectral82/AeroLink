# AeroLink: интеграция данных о воздушных судах через API

AeroLink - учебный проект на Python, реализующий интеграцию с внешними API для сбора, обработки и сохранения данных о 
самолётах. Проект демонстрирует типичные задачи разработчика: работу с REST‑API, применение принципов ООП и SOLID, 
валидацию данных, сравнение сущностей, сохранение результатов и покрытие кода тестами.

## Особенности проекта

- **Получение географических границ стран** через API Nominatim (nominatim.openstreetmap.org) — используется параметр 
- `boundingbox` для определения прямоугольной области поиска.
- **Сбор данных о воздушных судах** в заданной области через API OpenSky Network (opensky-network.org).
- **Преобразование сырых данных** в объекты предметной области с валидацией и нормализацией значений.
- **Сравнение самолётов** по ключевым параметрам (скорость, высота полёта).
- **Фильтрация и сортировка** данных: топ‑N самолётов по высоте, фильтрация по стране регистрации, выборка по диапазону 
- высот.
- **Сохранение и загрузка данных** в JSON‑файл через универсальный интерфейс хранилища (с возможностью замены на БД или 
- другое хранилище).
- **Консольный интерфейс** для взаимодействия с пользователем: ввод страны, параметров фильтрации и вывода результатов.
- **Покрытие тестами** основных компонентов (≥ 70 %): клиенты API, модель самолёта, адаптер преобразования, хранилище, 
- логика фильтрации и сортировки.

## Используемые технологии и библиотеки

- **Python 3.14+** — версия языка, соответствующая требованиям проекта.
- **requests** — для выполнения HTTP‑запросов к внешним API и обработки ответов (включая проверку кодов состояния).
- **Poetry** — управление зависимостями и виртуальным окружением.
- **pytest + pytest-cov** — тестирование и измерение покрытия.
- **Black, isort, flake8, mypy** — обеспечение качества и единообразия кода.

## Архитектура и ключевые принципы

- **Абстрактные базовые классы** (наследование от `ABC`, использование `@abstractmethod`) для клиентов API и хранилищ 
  — обеспечивают единый интерфейс и возможность замены реализаций.
- **Инкапсуляция данных** в классе `Aeroplane`: атрибуты скрыты от прямого изменения, инициализация проходит валидацию.
- **Соблюдение принципов SOLID**: разделение ответственности между адаптерами, сущностями, клиентами API и хранилищами.
- **Обработка исключений**: корректная реакция на ошибки сети, некорректные данные, проблемы с файлами.
- **Расширяемость**: заглушки для методов, которые могут понадобиться при интеграции с БД или другими форматами 
  хранения.

## Требования

- Python ≥ 3.14.
- Poetry для установки зависимостей.
- Доступ к интернету для запросов к API Nominatim и OpenSky.

> Примечание: OpenSky Network не требует API‑ключа, но для Nominatim обязательно указание корректного `user_agent`.
